## 1. 为什么"纯色填充 + 重绘"在这里成立

这批贴图有三个对自动化极有利的性质（实测）：

| 性质 | 实测依据 |
|---|---|
| **调色板极小** | 单图色数 ≤ 40，多数 ≤ 22；`palette.bin` 全库 252 色 |
| **背景近似常量** | 面板底是 `#315D31` 系绿色，横向基本无渐变 |
| **文字色固定** | UI 文字**只**用 4 个精确调色板色（见 §1.1） |

因此"定位文字 → 抹掉 → 原位置重绘"不需要任何图像模型，纯像素运算即可做到无损。

### 1.1 文字色白名单（穷举实测）

| 颜色 | 用途 |
|---|---|
| `#FFFBF0` | 白 —— 标题、按钮**常态** |
| `#FEE402` | 黄 —— 按钮**选中态** |
| `#29DF29` | 绿 —— 按钮**按下态** |
| `#9CAA7B` | 暗绿 —— **未选中**的标签页 |

> 这 4 色都在 `palette.bin` 内（索引 246 / 167 / 223 / 242）。

**灰色必须排除**：`#ABABAB` / `#C6C6C6` / `#E3E3E3` / `#8E8E8E` / `#717171`
只出现在滚动箭头、单选钮、窗口立体边与**文字抗锯齿环**上，**没有任何文字**。
把它们算进文字色会导致大面积误检。

## 2. 关键资产：Hzk16 字库

### 2.1 文件事实

| 项 | 值 |
|---|---|
| 路径 | `Army2_CHS/Hzk16`（**仓库内已跟踪**，CI 与本地一致） |
| 大小 | 202,966 B |
| 魔数 | `RSE\x1a`（`0x1A455352` 小端） |
| 几何 | **宽 13 × 高 13**，26 B/字形（2 B/行） |
| 字形数 | 6,768 |
| 数据起始 | `0x694C`（头部 `0x48` 处 DWORD） |
| 字体名 | `宋体`（头部 `0x20` 处 GBK 串） |

### 2.2 字形定位公式

与 [`../Army2_Extend_Dll/src/hzk16.cpp`](../Army2_Extend_Dll/src/hzk16.cpp) 的
`Hzk16Font::Glyph` 完全一致（该实现逐字还原自 AM2 中文版 exe `sub_426DB0`）：

```c
long long idx = (long long)trail + 94LL * (long long)lead - 15295LL;
long long off = 26LL * idx - 9688LL;
if (off < 0) off += 9776LL;
glyph = base + off;          // 26 字节
```

`lead` / `trail` 是 GBK 双字节的**原始字节**（不是 Unicode）。
例：`战` = GBK `D5BD` → `lead=0xD5, trail=0xBD` → `idx=4916` → `off=0x1CD70`。

> **note**：`idx < 373` 时公式给出的 `off` 落在文件头（如 `idx=373 → off=0x0A`），
> 读到的是元数据而非字形。真实汉字（GBK `lead ≥ 0xB0`）的 `idx` 从 1850 起、
> `off ≥ 0x960C`，**全部在 `data_start=0x694C` 之后**。
> 所以低 `idx` 区不需要特判 —— 实际翻译用不到那里。

### 2.3 ★ 字形对齐：13 位左对齐在 16 位行内

**这是本次唯一一个会静默损坏输出的坑，必须写死在文档里。**

每行占 2 字节 = **16 位**，而字形只有 **13 列**，这 13 列存放在**高 13 位**
（bit15..bit3），低 3 位恒为 0 填充。

```python
v = (g[y*2] << 8) | g[y*2+1]      # 原始 16 位
cols = v >> 3                      # ★ 必须右移 (16 - 13) = 3，才是 13 列字形
```

读错的后果：每个字**整体左移 3 像素、丢掉最左 3 列**，表现为"**每个字左边的
第一笔不见了**"。这个错误视觉上很像"字有点挤"，**极易漏看**。

实证（`战` 的首行）：

```
raw 16 位 : 0010000010100000   ← 真实数据
读低 13 位: 0000010100000      ← 错法：左移 3，首列已出界
右移 3 位 : 0010000010100      ← 正确
```

**与 C++ 实现的一致性**：`hzk16.cpp` 的 `TestBit` 用
`byteIdx = x>>3; bit = 7-(x&7)`，`x=0` 读到的是 `g[0]` 的 bit7 = 原始 bit15。
这正是"高 13 位"语义，两处实现互为佐证。

#### 回归判据（墨迹数黄金值）

不要用"最左列是否非空"做断言 —— `开`、`目`、`国` 等字的字形本来就留白，
不触及第 0 列，断言会误报。**用墨迹数**：

| 字 | 正确 | 错读（未右移） |
|---|---|---|
| 开 | 46 | 39 |
| 战 | 61 | 44 |
| 目 | 54 | 41 |
| 国 | 79 | 60 |
| 确 | 79 | 63 |
| 认 | 35 | 22 |

错读时墨迹数**系统性偏小 10~17 px**。全字库 15,222 个汉字中，91.3% 的字最左列
有墨，所以"整体左移 3 列"会造成每字左侧一笔的普遍缺失。

## 3. 处理流程

```
png_ai/*.png (126)
      │
      ├─ ① 行检测   精确文字色 → 连通域 → 同行聚类 → 按词间隙切分
      │                              → lines.json（盒坐标 + 精确文字色）
      │
      ├─ ② 抹字     掩码 = 精确前景色 ∪ 盒外背景亮度差 > tol，膨胀 2px
      │              同行左右锚点线性插值填充 → 全图吸附回调色板
      │
      ├─ ③ 重绘     Hzk16 点阵渲染译文 → 竖向居中、横向按列对齐
      │
      └─ ④ 回包     am3_dat.py pack → title.dat
                    逐对象 unpack 回读，与输入 PNG 逐像素比对
```

### 3.1 行检测：为什么不用背景估计

**试过并否决的方案**（都是真实的死路，记下来省得重走）：

| 方案 | 失败原因 |
|---|---|
| 中值滤波估局部背景 | 绿字 `#29DF29` 相对底色只亮约 **74**；15×15 窗口内笔画占多数，中值把**文字**当成了背景 |
| 形态学闭运算估背景 | 同上，1–2 px 笔画被闭运算吞掉 |
| 逐行众数估背景 | 标题行文字可占该行宽度 **80%+**，众数直接变成文字色 |
| 亮度阈值 + 连通域 | 底纹（绿色拉丝）与黑窗噪点大量误检 |

**最终方案**：既然文字色只有固定的 4 个**精确**调色板色，就**直接精确匹配**，
不做任何背景估计。这一步让误检归零。

随后：

1. **连通域**：`MIN_PX=4`、`MAX_H=16`、`MAX_W=26`（单字形上限）
2. **同行聚类**：y 重叠 > 50%
3. **按词间隙切分**：实测**词内最大间隙 16 px**、**词块间最小间隙 19 px**，
   故取 `MERGE_GAP=17` 作阈值，可正确分出 `PLAYER` / `COLOR TEAM` / `PLASTIC`
   这三个独立标签，又不切碎词组

> **跨行盒的例外**：`MAP / OBJECTIVE` 的 `MAP` 与 `OBJECTIVE` 之间有空隙，
> 被切成两个盒。渲染器支持 `span=行号` 参数：**先擦所有相关盒**（几何取并集），
> **再整体写一次**，避免"擦一半、写两次"。

### 3.2 抹字：锚点必须保留

掩码 = 精确前景色 ∪ 与**盒外**背景亮度差 > `tol(14)`，再 3×3 膨胀 2 次。

填充用**同行左右最近非掩码像素的线性插值**。背景在这些面板上横向近乎常量，
插值能保住底纹过渡而不留补丁痕迹。

**两个必须遵守的细节**（都是踩出来的）：

| 细节 | 违反后果 |
|---|---|
| **左右各留 10 px 边距取样** | `x1/x2` 是"精确色"首末列，而抗锯齿灰晕还会往外延伸 2~3 px。边距不足时灰晕被当成背景锚点，插值出一条**灰色横带** |
| **两端各留 3 列强制为背景锚点** | 标题行文字占该行 80%+，膨胀后**整行被掩**，左右都取不到值 → 抹字**静默失效** |

膨胀后强制：

```python
mask[:, :3] = False        # 左锚点
mask[:, W-3:] = False      # 右锚点
```

#### 自检

抹字后立刻在盒内重数原文字色像素，`> 2` 即记为残留并打印告警。
本次最终结果：**残留 0**。

### 3.3 颜色必须吸附回调色板

本作贴图是 **256 色索引图**。线性插值必然产生调色板外的过渡色；打包时
`am3_dat.py` 会做最近色匹配（实测最大距离 5），**会在纯色背景上留下肉眼可见的噪点**。

所以在 `process()` 末尾对**整图**做一次吸附：

```python
# 精确命中则原样；否则取曼哈顿距离最近的调色板色
arr = snap_to_palette(arr)
```

实测：吸附前 102/126 张含非调色板色（最多 931 px/张），吸附后 **0/126**。

### 3.4 排版规则

| 项 | 规则 |
|---|---|
| 竖向 | 以原行墨迹中心为中心（不按盒高，避免基线漂移） |
| 横向 | 默认居中；**同一列出现 ≥3 个文字块时自动左对齐**（识别列表/标签列） |
| 字距 | 默认 1 px（`tracking` 可调） |
| 描边 | **默认不加**，见下 |

#### 关于描边

原英文看起来有黑边，实测**不是描边**：那是**抗锯齿灰环**（调色板里恰好是
`#ABABAB` / `#C6C6C6` / `#8E8E8E`）。

Hzk16 点阵本身是 **1 bit 无抗锯齿**，再套一圈描边只会糊掉笔画。故默认不加；
确有需要时用译文表 `outline=RRGGBB` 显式指定。

### 5.1 完整流程

```powershell
$PY = "<python>"
$W  = "I:\LocalGames\Army Men\_am3_title_work"

# 0) 解包（若 png_ai 不存在）
python Tools/am3_dat.py unpack "<游戏目录>/title.dat" Army3_Object_CHS/title
```

### 5.2 译文表格式

`translations.tsv`（UTF-8、TAB 分隔，`#` 与空行忽略）：

```

```

| 参数 | 说明 |
|---|---|
| `color=RRGGBB` | 覆盖文字颜色（默认沿用原文精确色） |
| `outline=RRGGBB` | 指定描边色（默认不加） |
| `align=left\|center\|right` | 覆盖自动对齐判定 |
| `dx=N` / `dy=N` | 微调偏移 |
| `tracking=N` | 字距（默认 1） |
| `span=行号,行号` | **跨多个行盒的一条文本**，一并擦除、只写一次 |

修改译文后只需重跑 §5.1 的第 2、3 步。

## 6. 踩坑清单（按危害排序）

| # | 坑 | 症状 | 根因 | 判据 |
|---|---|---|---|---|
| **1** | **Hzk16 字形未右移 3 位** | 每个字**左边第一笔缺失**；易被当成"字有点挤"而漏看 | 13 列字形左对齐在 16 位行的高 13 位，直接读低 13 位会整体左移 3 px | 墨迹数系统性偏小（`战` 61→44）；`selftest()` 黄金值断言 |
| **2** | **抹字锚点被膨胀吃光** | 原文**毫发无伤**，新旧文字叠在一起 | 标题行文字占该行 80%+，掩码膨胀后整行被掩，插值左右取不到值 → **静默失效** | 抹字后盒内重数原文字色，> 2 即告警 |
| **3** | **取样边距不足** | 文字位置出现**灰色横带** | `x1/x2` 是精确色首末列，抗锯齿灰晕还往外 2~3 px；灰晕被当锚点 | 左右各留 10 px 边距 |
| **4** | **线性插值产生调色板外颜色** | 背景上出现**噪点** | 索引图 + 插值过渡色；打包时就近匹配（距离可达 5） | 全图颜色 ⊆ `palette.bin` |
| **5** | **把抗锯齿当描边** | 汉字被套边后**笔画糊掉** | 原英文的"黑边"是抗锯齿灰环，不是描边 | 逐字采样 `fg` 邻域色，得到的是灰阶而非深色 |
| **6** | **用亮度阈值/背景估计找文字** | 绿字漏检 或 底纹/黑窗大量误检 | 绿字与底色亮度差仅 ~74；底纹是低对比噪声 | 改用 4 色精确匹配后误检归零 |
| **7** | **跨框文本被当两条** | `MAP / OBJECTIVE` 被擦两次写两次 | 词块间隙 > `MERGE_GAP` 时切成两盒 | 用 `span=` 参数合并处理 |

### 6.1 为什么这些坑特别危险

坑 1、2 都是**静默失败**：脚本正常退出、日志无异常、图像能打开，
只有肉眼逐字看才能发现。因此两处都加了自动化断言：

- 字形对齐 → `Hzk16.selftest()`，并作为 `am3_title_build.py` 的**前置闸门**，
  不通过直接中止构建
- 抹字残留 → 每处处理后立即重数，`> 2` 打印告警

**教训**：像素级输出必须配**数值判据**（墨迹数、颜色集合、像素差异计数），
不能只靠"输出没报错"。
