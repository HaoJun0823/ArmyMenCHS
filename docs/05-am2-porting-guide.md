# 2 代 → 3 / 4 代移植指南

> 3 代（`Army Men: Toys in Space`）与 4 代（`Army Men: World War`）引擎与 2 代
> **几乎一致**（不同于 1→2 代的巨大差异）。本文把"哪些能照搬、哪些必须重测"
> 逐项列清，避免重复 2 代那 6 轮弯路。
>
> 技术原理见 [`05-am2-technical-archive.md`](05-am2-technical-archive.md)。

---

## 0. 先看这张表：3 类工作

| 类别 | 含义 | 工作量 |
|---|---|---|
| 🟢 **可照搬** | 直接复用，不需要改 | 低 |
| 🟡 **需重测** | 结构相同但地址/常量要重新测量 | 中 |
| 🔴 **需重做** | 每代不同，无法复用 | 高 |

## 1. 逐项对照

### 1.1 exe 与识别 🟡

| 项 | 处理 |
|---|---|
| `TimeDateStamp` / `SizeOfImage` | 🟡 每代不同，用于档位识别 |
| ImageBase | 🟢 实测三代都是 `0x400000` |
| 位数 / 加壳 | 🟡 需重新确认（1 代与 2 代都是 32 位无壳） |
| VA/RVA 换算 | 🟢 `VA = RVA + 0x400000` |

识别逻辑照抄 `target.cpp` 的 `MakeProfiles()`：按 exe 名 + 大小 + 时间戳
选档位，再做**逐 hook 签名校验**，任一失败即 fail-closed（不 hook，保持英文）。

> ★ fail-closed 很重要：签名不符还硬 hook 会把 jmp 写到错误函数上，
> 直接崩溃且难以定位。宁可完全不汉化。

### 1.2 文字渲染器 🟡

| 项 | 处理 |
|---|---|
| 渲染器**个数** | 🟡 必须重新确认。2 代是 3 个，3 代可能不同 |
| 各渲染器 RVA | 🟡 重测 |
| 各渲染器**参数量与语义** | 🟡 重测（尤其 CENTER 的累加轴是 x 还是 y） |
| 入口指令边界 | 🟡 重测（决定 patchLen） |
| 分支判定"只看首字节" | 🟢 照搬（§9 的教训） |
| ASCII 段转调原 stub | 🟢 照搬 |
| 汉字逻辑尺寸 15 / 点阵 13×13 | 🟡 需确认 3/4 代是否同样 |

**怎么找渲染器**：在 IDA 里搜 `word_XXXXXX[262*font + c]` 形式的
"表索引 + 字节查表"模式，或直接对比中英文两版 exe 的差异函数
（`Tools/exe_scan/diff_exes.py`）。

### 1.3 文本测量函数 🟡

| 项 | 处理 |
|---|---|
| RVA | 🟡 重测 |
| "汉字 += 15" | 🟡 确认数值 |
| 必须 hook | 🟢 **照搬结论**（漏了会花屏，见 §2 弯路 4） |

> ★ 这一类"不画字但影响布局"的函数最容易漏。除了测量函数，
> 还要留意：**换行计算**、**居中计算**、**裁剪矩形设定**。
> 通用判据：**凡是消费字符串长度/宽度的函数，都要检查**。

### 1.4 全局量与共享表 🟡

| 项 | 处理 |
|---|---|
| `rcSrc2` / `rc` / `lockedSurf` / `primarySurf` / `enabled` | 🟡 地址重测，**语义照搬** |
| `surface` / `pitch` | 🟡 地址重测 |
| `atlasBase`（内容是堆指针） | 🟡 地址重测，★ 语义易错 |
| 表 `word[262*font+c]` 两张 + `dword[131*font]` | 🟡 地址重测 |

> ★ **`atlasBase` 的坑**：该全局里存的是 malloc 得到的**堆指针**，
> 取出来要原样当指针用，**不能再加 ImageBase**。

### 1.5 中文字库 🟢

| 项 | 处理 |
|---|---|
| `Hzk16` 格式（`RSE\x1a`、13×13、26B/字形） | 🟢 同一份字库可复用 |
| 偏移公式 | 🟢 照搬，并用 `verify_hzk_offset.py` 验证 |
| 字库文件本身 | 🟢 直接复制中文母盘的 `Hzk16` |

### 1.6 字符串表 🟡

| 项 | 处理 |
|---|---|
| 表项步长 / 首项 / 末项地址 | 🟡 重测 |
| 容量闸门（`cap = len(en)+1`） | 🟢 照搬 |
| INI 键用 RVA | 🟢 照搬 |
| "内存现状 == 英文原文"闸门 | 🟢 照搬（挡 RVA 算错） |

### 1.7 注入方式 🟡

| 项 | 处理 |
|---|---|
| 代理 DLL 名 | 🟡 **必须查该代的导入表** |
| 按名字 vs 按序号导入 | 🟡 关键判据（按序号导入不能用代理法） |
| UAL 的 `update\` 机制 | 🟢 照搬 |
| `scripts\*.asi` 约定 | 🟢 照搬 |

查法：

```powershell
python Tools/exe_scan/list_imports.py <目标 exe>
# 关注：候选 DLL 是否存在、其导入是 by name 还是 by ordinal
```

### 1.8 资产 🟡

| 项 | 处理 |
|---|---|
| 中文母盘是否存在 | 🟡 先确认（3/4 代是否有官方中文版需核实） |
| 差异移植原则 | 🟢 照搬（只覆盖确实含中文的文件） |
| 视频/音频判定 | 🟢 照搬方法（逐像素/波形比对） |
| BMP 汉化状态判定 | 🟢 照搬（**人工实图核对**，见 §3） |

### 1.9 工具链 🟢

| 工具 | 复用性 |
|---|---|
| `Tools/ci/build_dll_local_am2.py` | 🟢 改目标名即可 |
| `Tools/ci/verify_hook_sigs.py` | 🟢 按档位解析，改签名宏 |
| `Tools/ci/verify_stub_boundary.py` | 🟢 同上 |
| `Tools/ci/verify_hzk_offset.py` | 🟢 直接用 |

## 2. 2 代走过的 6 轮弯路（务必避免重蹈）

这 6 轮都发生在"花屏"这一个症状上。按时间顺序：

### 弯路 1：只 hook 1 个渲染器

现象：主菜单之外的文字完全不显示。
原因：引擎有 **3 个**渲染器，只挂了 LEFT。
教训：**先枚举全部文字路径，再动手**。

### 弯路 2：自绘裁剪，不复刻游戏逻辑

现象：文字渐显时花屏。
原因：我自己写了三层矩形求交 + 硬编码 640×480，
而原版是调用游戏自己的 `sub_42E220`。
`rcSrc2` 为 0 矩形时原版会**裁光不画**，我当成"未设定"照画 → 越界写出表面。
教训：**能转调就转调**，别复刻。

### 弯路 3：汉字步进用了 13

现象：长串文字越走越偏。
原因：官方汉字**逻辑尺寸是 15**（desc 与步进都用 15），点阵才是 13×13。
用 13 当步进 → 每字少走 2px → 累积越界。
教训：**逻辑尺寸 ≠ 点阵尺寸**。

### 弯路 4：漏 hook 文本测量函数

现象：任务简报窗口花屏，且退出对话框也花屏。
原因：`sub_446E00` 对每个字节查 ASCII 宽度表，汉字首字节查表越界 →
宽度算成垃圾 → 上层拿它当裁剪矩形 → 文字被切碎。
`rcSrc2` 是全局的，所以污染会扩散到其它界面。
教训：**找全所有消费字符串的函数**，不只是绘制函数。

### 弯路 5：分支判定多了 `s[1] != 0`

现象：持续花屏（首次正常）。
原因：见技术档案 §9 —— 逐字节渐显产生奇数长度串（末尾孤立汉字首字节），
该条件不成立就掉进 ASCII 分支 → 越界查表 → 把随机字节当 RLE 游程 → 刷大段颜色。
教训：**与官方的判定条件逐字符对齐**，不要"凭直觉加保护"。

### 弯路 6：靠目视验证字形正确性

现象：一度误判"字形偏移公式错了"，白费一轮。
原因：用"汉字看着像不像字"做判据 —— 13×13 里任何切片都像字。
教训：**判据要不可混淆**（用全角 ASCII 认字母），且**测试要自证区分力**。

## 3. 方法论：三条通用原则

### 3.1 逆向官方中文版，而不是反推英文版

2 代有官方中文版，它**必然**改动了全部文本处理函数。
把中英文两版 exe 逐函数对比，差异函数就是**完整清单** —— 不用猜。

```powershell
python Tools/exe_scan/diff_exes.py
# 输出：.text 差异区间 + 已知文本函数是否被改写
```

> 2 代实测：四个文本函数（LEFT/DIALOG/CENTER/MEASURE）在中文版里
> 差异字节数分别是 371 / 403 / 414 / 58 —— 全部被重写。
> 这就是"该 hook 哪些函数"的权威答案。

### 3.2 校验器必须自证

本项目踩过 4 次"校验器空转报绿"：

| 失效方式 | 表现 |
|---|---|
| 白名单过滤 | 新加的 hook 被静默忽略，仍打印"全部通过" |
| 硬编码条目数 | 只校验旧的 3 项，新增的第 4 项没查 |
| 累计到阈值就停 | 指令列表只有第一条，后续检查必然失败（假红） |
| 解析正则不匹配 | 匹配 0 条，脚本"什么都没查"却报通过 |

**要求**：
- 报出**实际检查的条目数**
- **断言覆盖度**（期望的 hook 类别必须都被查到）
- 空转即失败
- 尽量让测试**能区分正误**（如 `verify_hzk_offset.py` 的全偏移扫描）

### 3.3 区分"事实"与"推测"

本文档所有标 ✅ 的条目都注明验证方式；未验证的一律标 ❓。
2 代期间有多次"用确定语气包装猜测"导致走弯路，
例如"rc 是窗口消息设的"（实际由 `sub_40B070` 设）、
"字形公式错了"（实际是对的）。

## 4. 开工顺序建议

```
①  确认中文母盘是否存在 ─────────┐
②  确认 exe 位数 / 加壳 / 导入表 ─┤ 前置核查
③  确认 ASI 代理 DLL 可用 ───────┘
        │
        ▼
④  中英文 exe 逐函数对比 ──────── 拿到"文本函数完整清单"
        │                         （diff_exes.py）
        ▼
⑤  对每个文本函数：确认 RVA、参数、入口指令边界
    · patchLen 必须逐 hook 反汇编验证
        │
        ▼
⑥  测绘全局量 VA（渲染器用到的每一个）
    · 一律填绝对 VA
        │
        ▼
⑦  建 DLL 骨架：只 hook 不翻译，确认能加载、不崩
        │
        ▼
⑧  小批量试译（10~20 条），重点看**有渐显动画的界面**
        │
        ▼
⑨  全量翻译 + 差异移植资产
        │
        ▼
⑩  对账 + 校验 + 打包 + CI
```

**第 ④ 步是本指南的核心价值** —— 2 代是先做了 ⑤~⑧ 才发现漏了第 4 个函数，
绕了 6 轮。有官方中文版时，④ 能一次性给出答案。
